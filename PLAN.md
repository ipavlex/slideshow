# Android TV Слайдшоу — План проекта

> Рабочее название: **TV Slideshow** (уточнить финальное имя)
> Пакет: `com.pzarubin.tvslideshow` (заглушка, уточнить)
> Целевое устройство: **Xiaomi Mi Box** (Android TV)

---

## 1. Цель

Приложение-слайдшоу для Android TV с двумя источниками контента:

1. **Локальная папка** — выбор через системный SAF.
2. **Яндекс.Диск** — выбор папки на удалённом хранилище (дорабатываем во вторую очередь).

Несколько режимов показа (минимум «Кен Бернс» и «Классика»), управление перемоткой и скоростью с пульта.

### 4.2. Ключевая абстракция — `MediaSource`

Единый интерфейс для обоих сценариев:

```kotlin
interface MediaSource {
    /** Список элементов (фото/видео) в папке. */
    suspend fun list(): List<MediaItem>

    /** Стрим/файл для показа элемента (локальный или скачанный в кэш). */
    suspend fun open(item: MediaItem): MediaHandle

    /** Локальный кэш: прогресс/готовность. */
    fun preload(item: MediaItem)
}

data class MediaItem(
    val id: String,              // стабильный id (uri/path)
    val kind: Kind,              // PHOTO | VIDEO
    val name: String,
    val mimeType: String?,
    val sizeBytes: Long?,
    val modifiedAt: Long?,
    // источник хранения; для ЯД — remote path
)

data class MediaHandle(
    val uri: Uri?,               // локальный (SAF или кэш)
    val stream: InputStream?,    // или поток
    val kind: Kind,
)
```

**Сценарий 1 — `LocalFolderSource` (SAF):**
- Пользователь выбирает дерево через `ACTION_OPEN_DOCUMENT_TREE`.
- Сохраняем `takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)`.
- Листинг через `DocumentFile.fromTreeUri` (рекурсивно опционально).
- Фильтр по MIME: `image/*`, `video/*`.
- Показ напрямую по `Uri` (фото — декодер, видео — Media3). Кэш не обязателен.

**Сценарий 2 — `YandexDiskSource` (этап 2):**
- OAuth device-code → access/refresh token.
- Листинг: `GET /v1/disk/resources?path=...&fields=...`.
- Загрузка: `GET /v1/disk/resources/download?path=...` → временная ссылка.
- **Обязательный локальный кэш** (`SlideCache`, LRU) — стримить фото с Ken Burns по сети нельзя, нужен предзагруженный Bitmap/файл. Видео — прогрессивная загрузка через Media3 (поток) либо предзагрузка в кэш.

## 5. Модель слайдшоу

### 5.1. Режимы показа

| Режим | Поведение |
|---|---|
| **Кен Бернс** | Каждое фото: медленный pan+zoom (случайное направление/угол), кадрирование с заполнением экрана, плавный кроссфейд между слайдами. Видео проигрывается как обычно. |
| **Классика** | Статичное фото на весь экран (fit, без потерь), простой кроссфейд, фиксированная длительность. |

> Оба режима имеют общий движок; отличаются только рендерером фото и настройками длительности/перехода.

### 5.2. `SlideshowEngine` (машина состояний)

```
IDLE → LOADING → PLAYING ⇄ PAUSED → (END/LOOP)
```

- Держит плейлист + индекс текущего слайда.
- Таймер на основе `Handler`/`Coroutine` (точность ~16 мс).
- Длительность слайда = базовая × множитель скорости.
- **Прекэш**: заранее готовит `next`/`prev` (фото — декод, ЯД — скачивание в кэш), чтобы не было «рывков».
- События: `onSlideChanged`, `onStateChanged`, `onProgress`.

### 5.3. Перемотка и скорость (с пульта)

**Маппинг кнопок** (подтверждено):

| Кнопка пульта | Действие |
|---|---|
| `DPAD_LEFT` / `DPAD_RIGHT` | Предыдущий / следующий слайд |
| `DPAD_UP` / `DPAD_DOWN` | Изменение скорости (быстрее/медленнее) |
| `DPAD_CENTER` (OK) | Play / Pause |
| `MEDIA_REWIND` / `MEDIA_FAST_FORWARD` | Перемотка внутри видео / прыжок ±N слайдов |
| `MEDIA_PLAY_PAUSE` | Play / Pause |
| `BACK` | Выход в меню |
| `MENU` | Быстрое меню (режим, скорость, порядок) |

**Скорость** — множитель интервала между слайдами: `0.25× / 0.5× / 1× / 1.5× / 2× / 4×`. Для видео — скорость воспроизведения (`setPlaybackSpeed` в Media3).

**Перемотка**:
- Фото: мгновенный переход на предыдущий/следующий.
- Видео: кнопки rewind/ff делают `seek` внутри видео; left/right — переход на соседний слайд.
- Предусмотреть OSD-оверлей с индикатором: номер слайда, имя, скорость, прогресс.

### 5.4. Медиа-сессия

`MediaSession` (media3-session) — обязателен для корректной обработки медиа-кнопок на TV и «Now Playing» карточки. Слайдшоу позиционируем как плейлист медиа.

## 6. Построение плейлиста

`PlaylistBuilder`:
- Фильтр: только фото/видео (по MIME/расширению).
- Сортировка: по имени / по дате изменения / случайно.
- Опции: рекурсивный обход подпапок, перемешивание.
- Пропуск битых/нечитаемых файлов (graceful skip + лог).

## 7. Сборка и подпись (sideload)

- **Gradle Kotlin DSL**, один модуль `app`.
- `minSdk 28`, `targetSdk 34`, `compileSdk 34`.
- Release-подпись: debug-ключ для начала (удобно для sideload), позже — собственный keystore.
- `buildTypes.release { minifyEnabled true (R8) }` после стабилизации.
- Целевая команда: `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`.
- Флаг `android.leanback` + `LEANBACK_LAUNCHER` intent-filter, `android.hardware.touchscreen` not required.
- Banner для TV-лаунчера (`android:banner`).

## 11. Риски

| Риск | Митигация |
|---|---|
| SAF-пикер на TV неудобен | Фаза 1 — запасной план: свой браузер папок (§10.1) |
| Плавность Ken Burns на слабом GPU | Аппаратное декодирование, ограничение размера декодируемых Bitmap, `inSampleSize` |
| Большие видео (4K) на Mi Box | Прогрессивная загрузка, ограничение разрешения при необходимости |
| OAuth Я.Диск без браузера | Device-code flow решает; хранение refresh-token в зашифрованном хранилище |
| Отзыв SAF-разрешения / перезагрузка | Пере-валидация URI при старте, повторный выбор папки |
