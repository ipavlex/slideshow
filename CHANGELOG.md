## [0.9.10] — 2026-10-10

### Исправлено
- Чёрные экраны вместо фото в режиме Ken Burns (регрессия 0.9.7): отрисовка
  возвращена на прямой `Canvas.drawBitmap`. Вариант через `BitmapShader`
  обращался к пикселям bitmap'а на RenderThread, а приложение интенсивно
  переиспользует и recycle-ит bitmap'ы при каждой смене слайда — на
  ТВ-устройствах это давало чёрные кадры. Клампинг панорамирования
  (защита краёв при zoom-out) сохранён.

## [0.9.9] — 2026-10-10

### Добавлено
- Возобновление слайдшоу: последний показанный слайд запоминается для каждого
  источника (`ResumeStore`, SharedPreferences). При повторном запуске того же
  источника появляется диалог «Продолжить / С начала»; «С начала» сбрасывает
  сохранённую позицию. Если сохранённый слайд отсутствует в новом плейлисте
  (файлы удалены/изменились) — показ стартует с начала без диалога.
- `SlideshowEngine.start(startIndex)` — старт показа с произвольного индекса.

## [0.9.8] — 2026-10-10

### Добавлено
- Публичные альбомы Яндекс.Диска по ссылке (`disk.yandex.ru/a/…`): кнопка
  «Альбом по ссылке» на главном экране, ссылка запоминается для повторного
  запуска. OAuth не требуется — альбом должен быть опубликован по ссылке.
- Клиент веб-галереи Я.Диска (`YandexPublicAlbum`): виртуальные альбомы
  недоступны через официальный REST API, используется внутренний API
  публичной страницы (bootstrap store-prefetch, сессионный sk с куки,
  повтор при wrongSk, постраничный `fetch-album-list`). Фото отдаются
  готовыми preview-ссылками, видео — скачиванием оригинала.
- Коллекции альбомов: спец-папка `_albums` в корне Диска, в подпапках —
  ID или ссылки альбомов. Экран «Альбомы» (из браузера Диска) сканирует
  папку, показывает сетку с обложками; запуск слайдшоу по альбому или по
  всем сразу. Данные альбомов кэшируются локально (`AlbumStore`) —
  повторные запуски без сетевых запросов, кнопка «Обновить» — принудительный
  рескан. Один недоступный альбом не ломает скан.
- Новый источник `AlbumSource` в слайдшоу (типы `album` / `albums`),
  создание источника и обработка ошибок загрузки — асинхронно, с тостом
  при неудаче.

## [0.9.7] — 2026-10-10

### Исправлено
- Ken Burns: мерцание краёв изображения при зуме — отрисовка переведена на
  `BitmapShader` с `TileMode.CLAMP` (билинейный фильтр больше не семплирует
  прозрачные пиксели за границей bitmap'а).
- Ken Burns: панорамирование клампится по фактическому запасу каждой оси
  (поле в letterbox / переполнение в cover) — при zoom-out край изображения
  больше не уезжает за экран и не появляются «дёргающиеся» чёрные полосы.

### Изменено
- Кроссфейд слайдов: Ken Burns уходящего слоя замораживается на время
  перехода — каждый кадр перерисовывает только входящий слой, композитинг
  заметно дешевле на слабых ТВ-приставках.
- Безопасный порядок освобождения bitmap'ов: снимаются со слоёв (сброс
  шейдера) до `recycle()` — защита от краша на recycled bitmap.

## [0.9.6] — 2026-10-10

### Исправлено
- Подключение к Яндекс.Диску: OAuth-приложение зарегистрировано как confidential
  («Для доступа к API или отладки»), токен-эндпоинт требует `client_secret`.
  Секрет теперь читается из `app/secrets.properties` (`YANDEX_CLIENT_SECRET`)
  и передаётся в запросах `/device/code` и `/token` (device-code и refresh).

## [0.9.4] — 2026-10-10

### Добавлено
- Настройка «Показывать плашку с названием файла» — можно полностью скрыть
  OSD (название, счётчик, скорость, прогресс видео).

### Исправлено
- Скорость показа не действовала на видео — теперь применяется и к
  воспроизведению (playbackSpeed).
- Смена скорости посреди слайда перезапускала полную длительность — теперь
  пересчитывается остаток времени показа, реакция мгновенная и предсказуемая.
- Скорость больше не закольцовывается: на краях диапазона (0.25x / 4x)
  дальнейшие нажатия игнорируются.

## [0.9.3] — 2026-10-10

### Исправлено

### Изменено

## [0.9.2] — 2026-10-10

### Исправлено
- Долгий чёрный экран перед показом HEIC-фото: слайды теперь предзагружаются
  (prefetch следующего фото во время показа текущего), а таймер слайда стартует
  только после фактического показа — медленный программный декод HEIC больше не
  приводит к пропуску слайда или чёрной паузе. Добавлена страховка: если фото не
  показалось за 30 с (зависла загрузка/декод), слайд пропускается.
- Медленные миниатюры в браузере папок: дисковый кэш миниатюр (JPEG в cacheDir,
  ключ — путь+размер+mtime) — после первого просмотра папка открывается мгновенно;
  параллельные декоды ограничены двумя, чтобы HEIC-декоды не забивали все ядра.

## [0.9.1] — 2026-10-10

### Исправлено
- Пикселизация фото в слайд-шо: декод теперь под фактический размер на экране
  («cover» + запас под зум Кен Бёрнса), а не «fit within» — 4:3-фото на 16:9-экране
  больше не растягивается при отрисовке в 1.33–1.5×.
- Слишком сильное приближение вертикальных (и квадратных/панорамных) фото в режиме
  Ken Burns: при несовпадении пропорций с экраном больше 1.5× фото показывается
  целиком (letterbox), при близких пропорциях — как раньше, с заполнением экрана.

## [0.9.0] — 2026-10-10
